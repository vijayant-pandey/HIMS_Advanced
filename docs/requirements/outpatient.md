### HIMS-OPD-001

| Field | Record |
|---|---|
| ID and title | HIMS-OPD-001 Doctor schedules and exceptions |
| Business/clinical reason | Before patients can be booked, each doctor's OPD time must be known: which department, which weekdays, which hours, how long a slot is and how many extra bookings are allowed, and when the doctor is away or the OPD is closed (spec 4.6 "doctor availability, appointment calendars"; P0 part 01 §4; D10 slots per session; D11 extra bookings). Leave already approved on the Leave page (rotas, HIMS-STAFF-012) must take sessions off without being entered twice. Owner: PO |
| Actors | Head of department and OPD scheduler (`schedules.manage` for the department; facility-wide grant for a whole-facility holiday); branch and hospital administrators (both permissions); front desk (`appointments.view`: sees sessions and free slots, not why a doctor is away); doctors (their own sessions on My schedule) |
| Preconditions | Doctors on the Staff page, posted in the department; after `migrate` (migration `scheduling.0001`) the roles hold the new permissions and the OPD scheduler role exists; feature **Appointments and outpatient visits** on (the default) |
| Main success path | Doctor schedules → department → Add weekly session (doctor, weekdays, hours, slot, extra bookings, from, until, note) → the week shows each day's sessions with their free slots → Doctor away / Holiday / Extra session → the answer lists the sessions taken off → the week shows them off (all or in part) → a session opens its free slots → Change (slots, extra, note) or End (last day, reason) → Cancel an exception brings the sessions back |
| Alternate/failure paths | Not a doctor, not working, not posted, department not active, first day in the past, slot does not fit, outside the department's opening hours, overlapping one of the doctor's sessions in any department → `409 SESSION_NOT_POSSIBLE` (or `SESSION_OVERLAP` from the database) with the reason; several weekdays all or none; exception in the past, over 366 days, times over several days, leave for a doctor not posted in the department, extra session clashing or on leave → `409 EXCEPTION_NOT_POSSIBLE`; whole-facility holiday without a facility grant → 403; changing an ended session → `409 SESSION_ENDED`; stale version → 409; feature off → `409 FEATURE_DISABLED` |
| Data effects | New tables `doctor_schedules` and `schedule_exceptions` (checks, an exclusion constraint refusing overlapping weekly sessions of one doctor, three indexes besides the foreign keys' own). Ending a posting ends the doctor's sessions there; ending employment ends all. Never deleted |
| Security classification | Internal (sessions); a doctor's away reason is Restricted (personal) and shown only to schedule keepers; no patient data. `appointments.view` is treated as patient data (calendars will show booked patients): never the supplier's support account |
| Audit requirement | `schedule.session.added`, `.changed` (before/after), `.ended` (reason), `schedule.exception.added` (kind), `.cancelled` (reason); console changes the same; area **Doctor schedules (OPD)** on the Audit log |
| Idempotency/concurrency | `Idempotency-Key` on adding sessions and exceptions; every change for one doctor locks the doctor's staff row; the database refuses overlapping weekly sessions; `version` on changes |
| Integration dependencies | None (no messages yet; patients are told with HIMS-OPD-002 / 004) |
| Acceptance criteria | A session on several weekdays appears on each with its slot count; approved leave on the Leave page takes it off without saying the kind of leave, leave asked shows "Leave asked"; part of a day away keeps the other slots on their usual times; a holiday closes a department or (with a facility grant) the whole facility; an extra session adds slots unless it clashes; the front desk sees sessions and slots but not why a doctor is away and changes nothing; a head of department sees and changes only their department; doctors see their own sessions; a posting or employment that ends ends the sessions; the console applies the same rules; the feature switch closes the screens for a facility |
| Test evidence | `apps/scheduling/tests/test_doctor_schedules.py` (13), `apps/scheduling/tests/test_schedule_invariants.py` (5: every database rule), `apps/demo/tests/test_demo_hospitals.py` (seed and `add_demo_doctor_schedules`), `apps/performance` (four queries, two screens and the console list at volume); screens `scheduling.test.tsx` (8); browser test `07-doctor-schedules.spec.ts` (3, with accessibility); manual steps [doctor schedules](../workflows/doctor-schedules.md). Reviewer: the PO, at PR review |
| Release risk | Low: new tables and screens; the only change to existing behaviour is that ending a posting or employment also ends OPD sessions. Rollback: revert the PR and `migrate scheduling zero` (the two tables are dropped). Booking into the slots: HIMS-OPD-002 |
