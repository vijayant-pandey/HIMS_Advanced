Python dependencies are pinned exactly in `backend/requirements/`, and npm dependencies are pinned
exactly with `package-lock.json`. Upgrades go through a PR with the full CI suite.

## Update 2026-10-30 (HIMS-PLAT-012): hash-locked Python lockfiles
- We choose packages in `requirements/base.in` (runtime) and `requirements/dev.in` (tools).
  `base.txt` and `dev.txt` are generated by `uv pip compile --universal --generate-hashes`:
  every package, including indirect ones, is pinned with SHA-256 checksums for all platforms.
- CI installs with `pip install --require-hashes`, the image with
  `pip install --require-hashes --no-deps`: a package that changed upstream, or one not in the
  lockfile, is refused. A test fails if a `.in` file and its lockfile disagree.
- Pick versions at least two weeks old unless a security fix needs a newer one; `pip-audit`
  checks both lockfiles in CI. How-to: [dependencies.md](../workflows/dependencies.md).
- npm: `package-lock.json` already records an integrity checksum for every package and CI
  installs with `npm ci`.
- New runtime packages in this change: OpenTelemetry API/SDK, OTLP HTTP exporter and the Django,
  Celery, psycopg and urllib3 instrumentations (1.45.1 / 0.66b1; 1.45.0 had a known CVE).
